# KPOP 粉丝站设计

日期：2026-10-16

2026-10-16 修订：不做账号、后台和自动抓取。站点是一组静态页面。数据在使用方自己的库里，页面只读一份同样形状的数据文件。访客不注册、不登录。

## 意图

国内粉丝群里每天三句问话：这周谁回归，今天谁生日，最近谁在涨、谁在掉。

把链接丢进微信或 QQ，对方打开就能看懂。页面是简体中文，主时间是北京时间。正文不依赖 YouTube、X 或 Instagram 打得开。

## 谁在用

看的人没有账号。关注只存在这台手机的浏览器里，用来把首页收成自己的团。换手机或清掉站点数据，关注就没了。

改数据的人直接改自己的数据库，再导出成页面能读的文件。站点里没有编辑后台。

## 页面

手机优先，单列，最大宽度 40rem。桌面只是变宽。

- 首页：未来七天的已定档、今天起七天的生日、昨天播放增量的涨 5 和跌 5。浏览器里有关注时默认只看关注；可以换到全部。没有关注时就是全部。关注范围内不足 5 个时不拿全站补。
- 日历：按月的日期列表，只含已定档。待定单独一节，只有窗口原文，没有钟点。可以按类型筛选。
- 发行页：谁、作品名、类型、状态、北京时间、韩国时间、备注、官方出处。作品名为空时写「作品名未公布」。待定不显示钟点。
- 人物页：中文名、外文名、公司、出道日、生日、成员、官方账号。有频道时写出当前订阅数，以及当天、近 7 天、近 30 天的播放增量和订阅增量。没有频道时不出现这些数字，也不显示 0。团体和 solo 可以关注，成员不行。
- 变化榜：全站，不看关注。时间窗是当天、近 7 天、近 30 天。指标是播放增量或订阅增量。涨和跌分开。增量为 0 的不进榜。没有窗口开始时的快照不进榜。开始总量为 0 时不显示百分比。
- 搜索：按中文名和常用外文名包含匹配。

每条发行、每个人、每张榜都有自己的地址。

## 数据

页面读取 `web/data/db.js` 里的 `window.FAN_DB`。这是数据库导出的形状，不是第二套业务规则。

- `people`：`id`、`kind`（`group`、`solo`、`member`）、`name_zh`、`foreign_names`、`company`、`debut_on`、`birthday`（`MM-DD` 或 `YYYY-MM-DD`）、`links`（`label` + `url`）、`youtube_channel_id`、`group_id`。`published: false` 的人不出现。
- `events`：`id`、`person_id`、`title`、`type`、`status`（`scheduled` 或 `tentative`）、`starts_at`（UTC 的 ISO 时间）、`window_text`、`note`、`sources`（`label` + `url`）。`published: false` 的，或没有出处的，不出现。
- `snapshots`：`person_id`、`taken_at`、`view_count`、`subscriber_count`。

类型只有这些：正规专辑、迷你专辑、单曲、先行曲、出道、演唱会、签售、快闪、其他。

时间窗按北京时间的自然日。当天是今天 0 点到现在。近 7 天从今天往前第 6 天的 0 点到现在。近 30 天从今天往前第 29 天的 0 点到现在。昨天是上一个完整自然日。未来七天是今天到往后第 6 天，含今天已经过去的发行。

成员即使写了频道 ID 也不进榜。关注一个团时，首页包含这个团的成员生日，以及挂在成员身上的发行。

## 不做

- 注册、登录、邮箱、微信登录。
- 编辑后台、自动抓 YouTube、Instagram、微博。
- 长文、百科、图库、商城。
